# RadioPass — Developer Handover

**Prepared 9 August 2026.** Everything below was verified by running it, not assumed.

RadioPass is an interactive learning platform for the FRCR Part 1 exam (UK radiology). It teaches physics and anatomy through browser simulations the learner manipulates directly — rather than static notes. The founder is a radiology doctor, not a professional developer; the code was written with AI assistance.

**What we want from you:** an independent security and quality review before this goes live and takes payments. Please be blunt. Nothing here is precious.

```bash

npm install
```

## 3. Security — what we already know

We did a first pass ourselves. Please verify all of it independently and assume we missed things.

### Already correct (please confirm)

- **`.env` is gitignored.** It holds only `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
- **The Supabase anon key is public by design** — it ships in the client bundle and is meant to. It is not a leaked credential.
- **Therefore Row Level Security is the entire security boundary**, and it is implemented in `radiopass-website/supabase/schema.sql`:
  - three tables (`qbank_progress`, `qbank_marks`, `us_progress`), all with RLS **enabled**
  - each policy is `for all using (auth.uid() = user_id) with check (auth.uid() = user_id)` — restricting both reads and writes to the owner
  - grants go to `authenticated` only, never to `anon`
  - no `delete` grant
- **No hardcoded secrets** were found in application source.

### Known issues we want your judgement on

**1. Admin passcode on the anatomy site — we believe low severity, please confirm.**
`ANATOMY CLAUDE/frcr-anatomy/src/lib/admin.ts` gates an authoring UI behind a passcode that ships in the JavaScript bundle, hashed with a weak custom hash, with a hardcoded fallback (`'radiopass-author'`) when `VITE_ADMIN_PASSCODE` is unset. Auth state is `localStorage.setItem('...','yes')`, so it can be bypassed from devtools in seconds.
*Why we think it's low severity:* that app makes **no network writes whatsoever** — the only `fetch` loads local image frames. Admin edits are localStorage overrides affecting one browser only. There is no shared data to compromise.
*What we want to know:* do you agree, and does it need hardening before launch or only before any multi-user authoring feature?

**2. Large JavaScript chunks.** The build warns on several bundles over 500 kB (largest ~859 kB raw / 228 kB gzipped). Performance, not security — but our audience is heavily mobile and international, often on mid-range Android over patchy connections. Worth your view on code-splitting.

**3. No version control at the root.** The parent folder is not a git repo. Two subfolders have their own `.git`. This is the biggest operational risk on the project — see §6.

### Please specifically check

- Supabase **email/password auth configuration** — rate limiting, email confirmation, password policy, and whether signups are open.
- Whether the RLS policies actually behave as intended when tested against a live project (policy text can be right while dashboard settings undermine it).
- Any XSS surface, particularly anywhere user-supplied or JSON-sourced content reaches `dangerouslySetInnerHTML`.
- Dependency supply chain beyond `npm audit`.
- The `.htaccess` generated by `npm run package` — headers, HTTPS redirect, directory listing.
- Whether anything sensitive is reachable in the built `dist/` output.

## 4. Architecture, briefly

- **Routing:** all routes are declared in `radiopass-website/src/App.tsx`, lazy-loaded via `React.Suspense`.
- **Physics labs:** `src/us/` (ultrasound, ~20 modules — the flagship, and deliberately free with no signup), `src/mri/`, plus CT, nuclear medicine and X-ray labs under `src/labs/`.
- **Question bank:** `src/qbank/` — 453 questions in `src/qbank/data/questions.base.json`, plus mock papers in `mocks.ts`.
- **Auth:** `src/lib/auth.tsx` — a thin React context over Supabase auth.
- **Progress sync:** one JSONB blob per user per domain, deliberately mirroring the previous localStorage shape so the data model didn't change when accounts were added.
- **Simulations are procedural.** Physics is computed and drawn to canvas/SVG at runtime — there are no video files and no stock imagery anywhere. Accuracy of the physics is a product requirement, so please flag anything that looks numerically wrong.
- **`src/reference/`** holds ~132 old prototypes deliberately excluded from the build. Not dead code to delete — an archive. Confirm it genuinely isn't bundled.

## 5. What is NOT built yet

So you can tell "missing" from "broken":

- **Payments.** None. Paddle is the intended provider (merchant of record, for cross-border VAT). Nothing is integrated.
- **Analytics.** None. Plausible is intended.
- **Email capture and transactional email.** Not built.
- **The National Mock engine** — a timed exam with an instant percentile scorecard. Not built. This is the launch centrepiece and the biggest upcoming build.
- **Anatomy integration.** The anatomy app is currently a separate build stitched in at deploy time rather than a true part of the platform.
